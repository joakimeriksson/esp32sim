## The layout the candidates exploit

`wasm_region.rs::generate` emits one WASM `loop` (depth `loop_depth`), then `n` nested `block`s,
then a `br_table` on local `NEXT`; chunk `k`'s code follows the `k`-th `end`, i.e. the end of the
block at ctl index `loop_depth + n - 1 - k`. So from any depth `D` inside chunk `current`:

* chunk `j` is reachable with `br (D + j - (loop_depth + n))`, and that block is still open exactly
  when `j > current`; at the chunk top level that label is `j - current - 1`.
* the old path is `NEXT = j; br (D - loop_depth)`, which re-enters the `br_table`. `NEXT` is a phi
  at the loop header, so TurboFan cannot fold it.

Every candidate keeps the credit/DIRTY check, the ACCX flush (EX178 rule) and the `pending` flush at
the edge exactly as they were; only the jump changes.

## Candidates

### edges-s1 — direct forward `br` (002316d7)

`region_edge`: when the target chunk index is `> current`, emit `br (depth + index - (loop_depth +
n))` instead of `NEXT = index; br loop`. Backward edges keep the `br_table`. The existing fallthrough
elision (`direct && index == current + 1 && depth == chunk_depth`) is untouched, so this converts
only edges that already emitted a branch. 13 lines in `wasm_region.rs`.

Directed test `forward_edges` (`wasm_tests/regions.rs`): an 8-chunk graph where a conditional's taken
target is two chunks ahead (label 1 from inside the branch `if`) and another edge needs label 2; two
counter bits pick the path so every edge runs under the harness's credit cuts and probes.

Prediction: small win, no behavior change at all — the census confirms identical formation, calls,
retirement and exit kinds, with 0.3% fewer generated bytes (the removed `NEXT` stores).

### edges-s2 — self-loop chunks as WASM loops (8f6cb6fb, stacks on s1)

A chunk whose successor set contains its own head, or which is exactly a hardware-loop body
(`lbeg == chunk.pc && lend == chunk_end`), is wrapped in a WASM `loop` opened right after the block
`end` that starts it and closed before the next chunk's `end`. `region_edge` sends a target equal to
the current chunk's head to that loop label (`depth - chunk_depth`) after the same credit/DIRTY
check. Other chunks still arrive through the `br_table`: the `loop` opcode sits after the block end
the table branches to, so table entry still works.

s2 also restates s1's forward label as `depth + index - (loop_depth + n)` (`n = heads.len()`), the
same value, but anchored on the block nesting so it stays correct now that `chunk_depth` can include
a self-loop.

Directed test `self_loops`: a `bnez`-to-own-head chunk and a single-chunk hardware loop whose body
ends exactly at LEND (counts 4, 1 and 0, so LOOPNEZ's skip path runs too), both under credit cuts at
every index and a probe on the head.

Related: EX063/EX160 retained self-loops in *own block modules* (weak screens) and EX034 was explicit
single-block self-branch chaining (no gain). This is a third mechanism: it keeps the region dispatch
structure and replaces only the back-edge's `br_table` hop, and it covers hardware-loop bodies, which
a single-block self-branch cannot.

Prediction: the largest of the four on pocket-tank, whose PIE kernels are hardware loops.
s1+s2 together leave every region counter identical to base and cut generated bytes 0.30% / 0.23%,
so the entire effect is the shape of the jump — a clean A/B for TurboFan.

### edges-s3 — fallthrough-first successor order (510cfc20, stacks on s2)

`successors()` now yields `[next, target]` for conditional branches (`Loopnez | Loopgtz` already
did), so breadth-first numbering makes the straight line chunk `current + 1` (no branch at all) and
the taken target a forward `br` (s1). One line, plus five chunk-order assertions in the region tests
that are the formation documentation.

Trade: the not-taken path loses a `br`, the taken path gains one. For a bottom-tested `bnez` loop the
exit chunk is now numbered before the body, so the loop-exit edge becomes backward (`br_table`) —
once per loop, not per iteration; the back-edge itself is still s2's `br`.

Census: formation changes as expected — core-1 chunks +4.9%, region instructions +6.4%, formation
failures 1005→990. The unplanned effect is the useful one: **core-1 `edge` exits fall 23.1%**
(1,096,413→843,231) and region calls fall 1.6%, i.e. the new numbering keeps hot successors inside
the region instead of spending MAX_CHUNKS/MAX_INSNS on the branch-taken side. Generated bytes +7.4%
on core 1.

Prediction: the best of the family on TinyDraw (mostly straight-line, branch-heavy checks); a smaller
win on pocket-tank.

### edges-s4a / edges-s4b — chunk granularity (d4b407d1 / a8ec26a2, stack on s3)

Region-only chunk cap `CHUNK_LEN` (the block decoder's `MAX_LEN = 32` untouched): s4a = 16 with
`MAX_CHUNKS` 128, s4b = 8 with `MAX_CHUNKS` 256. `MAX_INSNS` stays 512, so exit sites stay far below
the `1 << 13` tag limit (the 30 s run would have tripped that `assert!`).

Census: the intended effect appears — core-1 budget exits -11.5% (s4a) — but it is swamped. Core-1
`edge` exits **more than double** (1,096,413→2,292,517), region calls rise 7.85% (s4a) / 10.74%
(s4b) for 0.2-0.4% *less* work retired inside regions, and work per region call drops 8.5% / 9.7%.
Shorter chunks spend the region's chunk and instruction budget on continuation chunks instead of
reaching further, so regions cover the same code in more, smaller calls. s4b also inflates all
compiled module bytes 6.6% and compiled modules 6.2% (4257→4521).

Prediction: **both are losses**, s4b worse than s4a; they are queued because the budget-exit
reduction is real and only the M3 decides. A further reason to expect a pocket-tank loss: chunk
boundaries flush the EX178 ACCX local and cut `pie::coalesce` runs. On this evidence s4a is "the
better s4" for the TinyDraw pair.
