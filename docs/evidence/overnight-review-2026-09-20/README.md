# M3 Pro: main versus the open performance stack

The pre-review stack more than doubled browser throughput in two fixed-work workloads, while native Pocket Tank took **14.22% longer**. This quick screen compares main `d5446b4a` with the stack tip `661623ea` as it stood before the overnight review fixes. [Audited results and source identities](audit.json).

| Runtime and workload | Main median | Pre-review median | Wall-time change | Throughput ratio |
| --- | ---: | ---: | ---: | ---: |
| [Chrome Pocket Tank, 30 guest seconds](runs/pocket-tank/summary.json) | 58.69744 s | 28.54471 s | **51.37% less** | **2.056×** |
| [Chrome pinned TinyDraw battery](runs/tinydraw/summary.json) | 62.00874 s | 28.98565 s | **53.26% less** | **2.139×** |
| [Native Pocket Tank, 30 guest seconds](runs/native-pocket-tank/summary.json) | 47.11885 s | 53.82059 s | **14.22% more** | **0.875×** |

Each row uses two balanced pairs, baseline/candidate then candidate/baseline. Browser paired reductions were 51.3690% / 51.3705% for Pocket Tank and 53.1778% / 53.3332% for TinyDraw. These are screening measurements with no confidence interval or same-build control. They measure the whole change bundle, including the selected WASM inline threshold, and do not attribute speed or regression to a single PR. [Pocket Tank pairs](runs/pocket-tank/summary.json) · [TinyDraw pairs](runs/tinydraw/summary.json) · [native pairs](runs/native-pocket-tank/summary.json).

All eight browser arms passed the pinned work and output checks: Pocket Tank retired **10,073,833,775** instructions and TinyDraw retired **9,819,885,134**. Console hashes and non-WASM inputs matched within each workload, browser versions matched, all workload verdicts passed and JIT failures were zero. All four native arms retired core 0 **4,446,180,089** plus core 1 **5,627,653,686** instructions, produced the same console hash and exercised the native JIT. Image/audio equality was not checked. Frame publication counts can differ across this bundle. [Audit](audit.json) · [audit implementation](audit.mjs) · [native run details](runs/native-pocket-tank/summary.json).

Measurements ran serially on the **Apple M3 Pro, 12 cores, 36 GB**, with Chrome **153.0.8010.53 / V8 15.3.76.13** and Rust **1.98.1**. Both WASM builds use release mode with no diagnostic features or wasm-opt. The main build has no explicit Rust flags; the candidate uses `-Cllvm-args=-inline-threshold=4000`, matching its build script. Native binaries use the default release profile without explicit features or Rust flags. No builds ran concurrently with timing. Ambient desktop activity was not disabled. [Host](host.txt) · [toolchain](toolchain.txt) · [main WASM build](runs/failed-old-glue/baseline/build.json) · [candidate WASM build](runs/failed-old-glue/candidate/build.json) · [serial native runner](native.sh).

The browser comparison uses identical current JavaScript glue for both frozen WASM artifacts. It measures runtime performance under that common harness, not historical page behavior. The current harness imports `experiments.mjs`, which main's old glue lacks. An initial attempt therefore never executed firmware; its records remain in `runs/failed-old-glue`. Another setup attempt used the host's default Rust version without the WASM target and failed before timing. Neither supplied a completed timing sample. The frozen artifacts were built at the exact revisions recorded in their `build.json` files, whose metadata is carried into the successful runs. [Browser runner](run.sh) · [initial target failure](runs/failed-default-toolchain/baseline/build.log).
