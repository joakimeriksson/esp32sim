# Queued browser output: measured snapshot savings

Queued browser output now skips preparing a late-join snapshot that only socket clients consume. Live frames and console output retain their existing delivery path. Native socket clients still receive the late-join snapshot. The change is three production lines plus a regression test that checks live frame bytes and avoids a second display copy.

The complete TinyDraw battery used 1.67% less median wall time across three matched pairs. Each candidate run was faster than every baseline run. A separate fixed-helper-table experiment showed no gain and was not adopted.

| Experiment | Baseline seconds, runs 1–3 | Candidate seconds, runs 1–3 | Median baseline → candidate |
| --- | --- | --- | --- |
| Skip unused snapshots | 122.3525, 121.9741, 124.5816 | 120.3123, 119.9861, 120.8475 | 122.3525 → 120.3123 s (1.67% less) |
| Fixed helper table, not adopted | 122.0338, 121.2861, 120.4704 | 120.3964, 123.5961, 121.7430 | 121.2861 → 121.7430 s (0.38% more) |

Each experiment ran A1/B1/B2/A2/A3/B3, using a fresh dedicated headless Chrome process for each run. The snapshot experiment finished before the helper experiment began; no other emulator benchmark or build ran concurrently. The host was an Apple M1 Pro with 10 CPU cores and 32 GiB RAM, macOS 27.0, Chrome 152.0.7977.77 and V8 15.2.124.19. These are unpaced battery throughput measurements; they do not measure interactive worker yielding, input latency, or silicon timing.

All 12 runs passed all 36 named boolean verdict gates. The separate `ssaa_receipt=yellow` is a fixed firmware receipt for an earlier supersampled-antialiasing performance limitation; it is outside those boolean gates and remains unresolved by this simulator change. Firmware hashes, complete console output, 9,819,885,134 guest instructions and 8,443,206,570 JIT instructions matched. Each run compiled 13,625 modules, released 9,720, reported zero compile failures, emitted 88,318,226 bytes cumulatively, and ended with 24,092,457 registered code bytes; peak registered bytes were 31,698,131. These byte counters describe generated modules, not browser memory.

Memory samples sum RSS for the dedicated browser and descendants every two seconds; shared pages may be counted repeatedly. Peak samples overlapped and show no consistent memory reduction. The retained optimization also passed 187 release workspace tests (seven external-input tests filtered), Clippy, and five WASM firmware demos. The archive includes those validation logs.

[Queue results](queue.json), [helper results](helper.json), and [environment](environment.json) retain timings, interval measurements, counters, input/module hashes and redacted file references. The interval timings include setup and console delivery between firmware markers; they are not isolated function measurements. The measured Rust baseline `a96fedf8` has the same tree as published commit `9f790da3`; capture-tooling revision `9eea9424` has the same tree as published commit `c667d90e`. Use `c667d90e` as the reproducible baseline. The archive contains the retained snapshot patch and the unadopted helper patch. Baseline and candidate WASM hashes identify the exact measured binaries.

Firmware source is [TinyDraw revision 7a157d44](https://github.com/aliceisjustplaying/tinydraw/tree/7a157d44a9da3312b1ecda2b45b116af2de28e63). With ESP-IDF v6.0.2 active, run `idf.py -B BUILD_DIRECTORY -DTINYDRAW_FIRMWARE_VARIANT=gate -DTINYDRAW_VECTOR_V2_TILE_SLOTS=604 build` from its `esp32` directory. The target is the Waveshare AMOLED 1.8-inch ESP32-S3, with 16 MiB flash and 8 MiB PSRAM. Obtain the S3 revision-0 ROM ELF from [Espressif’s 20241011 ROM release](https://github.com/espressif/esp-rom-elfs/releases/tag/20241011). Exact prebuilt firmware inputs are not distributed here. Rebuilding may change their hashes; use one identical firmware build for every A/B run and treat that as a new comparison.

To inspect the archived comparison, extract it under the repository checkout and run `python3 performance-package/summarize-performance.py` from the checkout root. To repeat measurements, check out the baseline source and apply the relevant archived patch in an isolated checkout, then build with `tools/wasm-build.sh`. Supply firmware matching the recorded hashes, adjust the archived assets map to local paths, and serve with `python3 tools/browser-benchmark/serve.py ASSETS_JSON --port PORT`. Run `python3 performance-package/run-battery.py http://127.0.0.1:PORT/battery.html NEW_OUTPUT_DIRECTORY` for each member of the stated run order. The runner uses macOS Chrome's standard application path. For the helper experiment, use the same baseline WASM in both variants and serve the candidate JavaScript with `--web-root CANDIDATE_CHECKOUT`. Three pairs on one host support this bounded result; they do not establish a universal speedup.
