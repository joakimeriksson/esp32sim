# EX167 tailchain: wasm tail calls through a jump cache

Worktree `/Users/alice/src/a/esp32sim-x2-tailchain`, branch `x2/tailchain`, commits 2e0a3515 (s1), f79bb646 (s2), 5cd860b2 (dry-stub diagnostic). All numbers below are pocket-tank under Node v24.16.0.

## Related experiments and what differs

EX033 (per-site two-block links, +42% bytes, no gain), EX153 (chaining inside the Rust wrapper, in base), EX164 (in-region call edges, unfinished), EX152 (turnover inside Cpu, rejected). EX167 differs in mechanism: one shared direct-mapped jump cache in linear memory, one shared exit stub per generated function, `return_call_indirect` (opcode 0x13) to the next module, zero Rust between hops. Generated bytes grow 1.2% (s1) and 4.7% (s2), not 42% (`jitBytes` 71,960,225 base, 72,817,885 s1, 75,345,019 s2; `tools/tailchain-census.mjs`, SECS=10).

## Step 2: tail-call support (risk line only)

Wasm tail calls ship in Chrome 112, Firefox 121 and Safari 18.2 ([MDN compat data](https://chromium.googlesource.com/external/github.com/mdn/browser-compat-data/%2B/HEAD/webassembly/tail-calls.json), [V8 blog](https://v8.dev/blog/wasm-tail-call), [WebKit Safari 18.2 notes](https://webkit.org/blog/16301/webkit-features-in-safari-18-2/)). The code is behind build features `tailchain` / `tailchain-bodies`; with the features off the emitted modules are unchanged.

## Step 3: what was built

- Jump cache: `Jc` entries in `CodeCache::jc` (`wasm.rs`), 4096 entries (feature `tailchain-1k`: 1024), index `((pc>>1)^(pc>>16)) & mask`. Filled by Rust in the EX153 loop right after `chain_target` admits the hop (`jc_fill`), emptied whenever `region_epoch` moves, on `reset`, on region formation (s2) and when the page-version array changes length.
- `run` arms the chain by setting `cpu.tc_base` only when EX153 itself would chain, `icache_fill == 0`, not observed and the fast-memory version pointer is the bus's version array. `h_exec` zeroes `tc_base` where it sets `HELPED`.
- Shared stub (`Gen::tail_stub`, `wasm_emit.rs`): every plain END/LEFT exit stores its result in a local and branches to one stub after the outermost block. The stub re-proves per hop: PC match, remaining credit >= chunk len, `boundary_bloom & (region bloom | pc_bit)`, `lcount == 0 || lend outside`, all region page versions. Then it adds its retired count to `cpu.tc_total`, stores the entry in `cpu.tc_last` and tail-calls. Any doubt returns to Rust exactly as today.
- s2 adds block bodies as sources and as targets. When credit < region chunk len (or the block has no region and Rust has stopped looking for one) the stub repeats `chain_target`'s test in wasm (decoded entry still holds this PC and this code index, both page versions unchanged, `pc_bit` bloom, no loop end inside the block) and tail-calls the block's own module with entry 0 and the unguarded helpers (`cpu.tc_helpers`).
- `tc_finish` (`wasm.rs`) decodes the result of the last module: region site table from the entry, or for a body the EX106 next index (`done << 19` on CODE_CUT) plus `chain_ei`. A chained-into region that REJECTs ran nothing and becomes a plain LEFT at the current PC.

### Mechanism and firing count

`Cpu::tc_depth` is zeroed at each Rust wrapper admission (`xtensa-lx7/src/jit/wasm.rs`), incremented before each nested call and decremented on unwind. ### Why the dry stub alone costs about 0.8 s

The production s2 stub is not one cheap cache test. From `Gen::tail_stub` in `xtensa-lx7/src/jit/wasm_emit.rs`, before committing a body hop it executes about **20 validation memory loads**: 4 common loads (`tc_base`, CPU PC, jump-cache PC and target length), then 16 body checks (slot, decoded-entry pointer/PC/code, cached code, two bloom words, LCOUNT/LEND/span and six loads for two page-version pairs). Accounting and call setup add about three more loads. A region hop executes about **16 validation loads for a two-page region**, up to **34 for eight pages**, then about three accounting/call loads. s3 adds one depth-cap load before validation, then depth and histogram loads when committing a call. Profile-counter loads are excluded because production builds do not enable `jit-profile`.

No cheap first condition skips most exits:

- Exit kind costs no runtime test: only statically known END/LEFT returns branch to the stub (`Gen::ret_value`).
- `tc_base == 0` already exits after one load, but covers only 8.08M of 96.47M stub entries (8.4%) in the s2 10 s census.
- A PC-tag miss returns after three production loads (four in s3) and covers 7.07M entries (7.3%).
- Moving the already-local `remaining == 0` check ahead of the PC hash could save three loads on about 3.73M entries (3.9%).
- Depth 8 adds a two-load early cap for 0.39M s3 entries (0.4%).
- 66.71M entries actually take a nested call, so they necessarily pay the full validity proof unless the cache's correctness contract is weakened.

The dry cost is therefore dominated by successful probes plus partial work on fallbacks, not by one missing early guard. A materially different next experiment would need a smaller validity contract or co-located entry facts, not merely reordered conditions. The coordinator corrected the existing `tailchain-s2-1k` queue NOTE to the s2 entry sizes: 152 KB per core for 1K and 608 KB per core for 4K.
