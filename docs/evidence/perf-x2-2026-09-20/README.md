## Conditions and uncertainty

M3 Chrome 153.0.8010.53 / V8 15.3.76.13, Pocket Tank 30 guest seconds, base `414c6e07`, release inline threshold 4000, no wasm-opt. Frozen baseline SHA-256: `cfbf86c5538646a47d9614469463ffbc666e391e1c69ee24f3ecb9e737567117`. Each screen has **two balanced pairs**, `screeningOnly: true`. Positive percentages mean wall reduction, computed as `100 × (1 − median(candidate)/median(baseline))`, not necessarily the median paired reduction. Negative reduction means more wall time. Pair values are retained in the catalog and every raw summary; no confidence interval or broad-workload confirmation is claimed.

A/A controls: [1](runs/control-aa-1.json) −0.18% (pairs −0.58%, 0.21%), [2](runs/control-aa-2.json) −0.31% (−0.38%, −0.24%), [3](runs/control-aa-3.json) 0.37% (0.38%, 0.35%). These show observed variation, not a universal noise threshold. Small singles and stack interactions remain uncertain.

[Recovery audit](recovery-wave1-audit.json) verifies all **100 arms**: 10,073,833,775 instructions, matching browser console SHA, passing work checks, frozen WASM hashes and zero JIT failures. The [41 raw summaries](runs/) preserve per-arm wall times, browser versions and full hashes for firmware/app, model, ROM, bootloader, partition table, WASM, workload manifest, harness and worker/glue inputs. [Frozen jobs](jobs.jsonl), [runner log](wave1-runner.log) and [harness snapshot](harness/) retain the run context. Browser console SHA is `9e8a66e483f741c80db1bd20c62bc43943697c2e6a0053a6af1f7d52af8c67dd`; it is not the separate Node exact-run console hash. Strict Node frame-content gates described in the notes do not turn the browser work/console checks into browser frame-hash validation.

## Wave 2 and provenance

[Sync receipt](audit/recovery-sync.log), [repeat-sync receipt](audit/recovery-sync-repeat.log) and [remote status](audit/recovery-remote-status.txt) cover nine dispatch2 jobs, three heads jobs and four spec2 jobs, with remote SHA checks. All 16 now have results: the [wave-2 audit](audit/wave2-results-audit.json) verifies **64/64 arms** against full frozen queue WASM hashes, 10,073,833,775 instructions, console equality within each campaign, `passed: true` and zero JIT failures. It also checks AB/BA order and recomputes medians and reductions. Each campaign has two balanced pairs, `screeningOnly: true`, not confirmation. Results and dispositions are recorded in the existing [EX150](../../experiments.md#ex150), [EX168](../../experiments.md#ex168) and [EX172](../../experiments.md#ex172) entries.

- **Dispatch2:** [audited notes](notes/dispatch2.md) and [machine-readable audit](audit/audit.json). Stack jobs include wave-1 s1–s6 and compare against plain base; their measured reductions are **not incremental wave-2 gains**. The full stack screens 1.22% lower (pairs 0.12%, 2.28%); neither this nor the other stack screens is a matched incremental comparison with the earlier 2.77% wave-1 result. t5 stays unqueued: workload gates passed but flash-invalidation proof and directed tests remain incomplete.
- **Heads:** [provenance audit](audit/recovery-heads-spec-audit.md) and [recovered test receipts](audit/recovered-jit-test-receipts.json). s1 was built from `14819b5a` plus a frozen patch equivalent to canonical `36bf6a8e`, not a clean build of that commit. Its 78,904-case receipt tests the s1 policy on later test-bearing source with sequential aliasing disabled. Native-suite-before-PR work remains open. [s3](runs/heads-s3.json) screens **3.78% lower wall time**, 32.410→31.187 s (pairs 4.15%, 3.39%); no adoption. The user approved an isolated heads-s3 + crumbs-all combined confirmation next; that combination has not been implemented or benchmarked.
- **Spec2:** [engine/gates](notes/spec.md) and the same provenance audit. K4/16/64 are exact conservative engines; tax1 is only a leader-mark lower-bound control, not matched engine overhead. The prior interruption was not negative evidence. Completed K4/K16/K64 screens show **−55.68% / −44.04% / −33.79% wall reduction**: losses that reject this implementation for adoption, not the broader speculative-execution idea. Tax1 screens −1.59%; it cannot be subtracted to isolate scheduling gains. Restore counts are not measured speedups.
