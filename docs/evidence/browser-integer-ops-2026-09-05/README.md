# Compile more integer operations into browser WASM blocks

The browser JIT now emits the integer operations MULUH, MULSH, ABS, SRA and SRC directly into WASM blocks. The complete TinyDraw battery used 2.51% less median wall time across three alternating pairs. All three candidate runs were faster than their paired baselines, and their observed ranges did not overlap. This result supports retaining the change for this workload; three pairs on one host do not establish a universal speedup.

| Pair | Baseline seconds | Candidate seconds | Candidate wall-time change |
| --- | ---: | ---: | ---: |
| 1 | 123.580130 | 121.193215 | -1.9315% |
| 2 | 124.646050 | 120.477680 | -3.3442% |
| 3 | 123.481650 | 119.277270 | -3.4049% |

Median wall time decreased from 123.580130 to 120.477680 seconds. Runs executed A1/B1/B2/A2/A3/B3 in fresh dedicated headless Chrome processes, with no other emulator/build work from this task during measurement. Chrome was 152.0.7977.77. These are unpaced battery throughput measurements without browser display rendering, not interactive yielding, input latency or silicon timing. Interval measurements include setup and console delivery between firmware markers.

All six runs passed all 36 named boolean verdict gates and executed 9,819,885,134 guest instructions. The separate `ssaa_receipt=yellow` is the firmware's fixed receipt for an earlier supersampled-antialiasing performance limitation; it is outside those boolean gates and remains unresolved by this change. Actual-WASM differential validation passed 41,711 cases and released 39,391 compiled modules. Clippy and five WASM firmware demos also passed; host SDK warnings remain in the logs.

Peak registered generated-code bytes increased from 31,698,131 to 32,704,962 (+3.1763%). Those counters describe generated modules, not browser memory. Summed browser RSS samples overlap and may count shared pages repeatedly; no resident-memory improvement is claimed.

A separate GPIO interrupt-summary candidate was not retained. It showed 2.5574% lower median wall time (122.856535 to 119.714610 seconds), but was slower in two of three pairs (+1.04595%, +0.85088%, -3.36996%) and its ranges overlapped. That experiment did not establish a repeatable gain and does not prove zero benefit. Its [separate raw archive](https://github.com/aliceisjustplaying/esp32sim/releases/download/browser-experiments-2026-09-05/gpio-summary-evidence-2026-09-05.tar.gz) retains all six runs, the patch and validation logs.

Both experiments start from queued-snapshot PR49 revision `0a517293a66ef374932c42a727bc31229f34a019`; the GPIO candidate is absent from the retained integer-operation change. The [integer-operation archive](https://github.com/aliceisjustplaying/esp32sim/releases/download/browser-experiments-2026-09-05/integer-ops-evidence-2026-09-05.tar.gz) contains exact patch/module hashes, captured harness sources, per-run results/events, memory samples, validation logs and reproduction instructions. Firmware/WASM binaries, browser profiles and compiled products are excluded.

Firmware source is [TinyDraw revision 7a157d44](https://github.com/aliceisjustplaying/tinydraw/tree/7a157d44a9da3312b1ecda2b45b116af2de28e63). With ESP-IDF v6.0.2 active, run `idf.py -B BUILD_DIRECTORY -DTINYDRAW_FIRMWARE_VARIANT=gate -DTINYDRAW_VECTOR_V2_TILE_SLOTS=604 build` from its `esp32` directory. Target: Waveshare AMOLED 1.8-inch ESP32-S3, 16 MiB flash and 8 MiB PSRAM. Obtain the S3 revision-0 ROM ELF from [Espressif's 20241011 ROM release](https://github.com/espressif/esp-rom-elfs/releases/tag/20241011). Exact prebuilt firmware inputs are not distributed here. Rebuilding may change their hashes; use one identical firmware build for every A/B run and treat that as a new comparison.

To repeat either experiment, extract its archive and follow `public-evidence/REPRODUCE.md`: use separate baseline checkouts, apply the archived candidate patch to one, build with `tools/wasm-build.sh`, adjust the asset maps to local files, and serve each map with `python3 tools/browser-benchmark/serve.py ASSETS_JSON --port 8792`. From the matching checkout, run `python3 PATH_TO_ARCHIVE/run-battery.py http://127.0.0.1:8792/battery.html NEW_OUTPUT_DIRECTORY` for each member of the recorded order. The runner uses the standard macOS Chrome path. Raw event arrays, memory samples and full logs remain in the archives; compact comparisons retain totals, intervals, outcomes and hashes.
